# BlockRadio 0.3.0 — Яндекс Музыка + YouTube

Minecraft Java **1.20.1**, **Fabric**, Java 17, Windows x64.
Требуются Fabric API для 1.20.1 и одинаковая версия BlockRadio у участников.
Spotify и SoundCloud не входят в проект.

## Установка без Python и BAT

1. В GitHub откройте PR #1 → Checks → последний успешный **BlockRadio Windows package**.
2. На странице запуска Actions скачайте artifact **BlockRadio-0.3.0-Windows**.
3. Из ZIP возьмите `source/build/libs/blockradio-0.3.0.jar`.
4. Удалите прежний BlockRadio JAR из `mods`, положите новый JAR и Fabric API.
5. Запустите Minecraft. Нажмите **M** → **Открыть полный плеер**.
   Также полный плеер открывается ПКМ по обычному проигрывателю.
6. Откройте вкладку **Аккаунты** и войдите в нужный сервис.

EXE уже встроен в JAR. Отдельный файл из `bridge/dist` не надо запускать.
Мод извлекает помощника в `<каталог игры>/config/blockradio/backend-<hash>.exe`,
запускает его без CMD и закрывает вместе с игрой. При аварийной остановке игры
помощник завершится после таймаута heartbeat (около 20 секунд).
Для двух отдельных экземпляров Minecraft используйте разные игровые каталоги.

## Первый вход в Яндекс

Аккаунты → Яндекс → Войти. Откроется локальная страница с кодом устройства и
ссылкой на Яндекс. Перейдите по ссылке, подтвердите вход и при необходимости
введите показанный код на странице Яндекса. Пароль вводится только у Яндекса.
Вернитесь в игру; состояние аккаунта обновляется автоматически.

Developer application и новые ключи не нужны. Сохранены `yandex-music==3.2.2`,
существующий device flow и существующий декодер. Эта интеграция неофициальная.
Сессия хранится в системном credential store; старый сохранённый токен поддержан.
Refresh token и expiration сохраняются, если сервис возвращает их.
Доступ к музыке зависит от аккаунта, региона и подписки каждого слушателя.
Аватар берётся из Яндекс ID, если музыкальный токен даёт такое право; иначе placeholder.

## Первый вход в YouTube

Существующий Google Cloud проект: `youtube-player-513401`.

1. В Google Cloud Console → Google Auth Platform → Clients скачайте JSON
   существующего **Desktop app** (YouTube Data API v3 должен быть включён).
2. Сохраните его на своём компьютере. Можно положить как
   `<каталог игры>/config/blockradio/client_secret.json`, либо выбрать файл
   через диалог при первом нажатии **YouTube → Войти**.
3. В браузере войдите тестовым Google-аккаунтом и разрешите `youtube.readonly`.
4. После входа вернитесь в Minecraft; профиль/аватар должны появиться автоматически.
5. Для воспроизведения нажмите **Видео**, затем **Подключить** в открывшейся
   странице и при необходимости Play в самом YouTube-плеере.

JSON остаётся локально, access/refresh tokens хранятся через keyring. Ничего из этого
не нужно отправлять разработчику или коммитить. При выборе внешнего JSON запоминается
только его путь: не перемещайте файл после настройки.
Google OAuth Testing требует добавления каждого пользователя в Test users;
повторный вход после истечения тестовой сессии возможен даже при исправном refresh.
OAuth открывает доступ к данным и не гарантирует вход того же аккаунта внутри IFrame.

## Интерфейс

- **Поиск**: Все / Яндекс / YouTube. `Ещё` догружает страницу результатов.
- **Моя музыка**: лайкнутые треки/видео, `Загрузить ещё`.
- **Моя волна**: небольшой персональный batch Яндекса; следующий трек запрашивается по необходимости.
- **Очередь**: общая очередь. `+` у результата добавляет трек; нажатие строки запускает.
- **Аккаунты**: вход/выход, имя, аватар и состояние двух сервисов.
- Нижняя панель: Previous, Play/Pause, Next, Видео, Auto, Stop, Seek, локальная громкость.
- **M**: компактный экран управления поверх игры. Это Screen с курсором,
  поэтому во время управления движение мышью не управляет камерой. Escape закрывает экран.
- Обложки загружаются асинхронно с ограниченным кешем и placeholder.

Autoplay по умолчанию ON. В конце трека сначала используется очередь.
Если она пуста: Яндекс запрашивает Мою волну; YouTube использует ещё не выбранные
результаты последнего поиска/списка текущего управляющего игрока.
Это НЕ персональное радио YouTube. Если кандидатов нет, плеер останавливается с сообщением.
Auto OFF запрещает автоматический переход; ручной Next остаётся доступен.
Previous использует историю общего плеера (до 50 треков), очередь ограничена 100 элементами.
Очередь и история живут в текущей игровой сессии и не сохраняются после закрытия мира.

## Essential / второй игрок

Оба устанавливают один и тот же JAR, Fabric API и совместимую версию Essential.
Хозяин открывает мир через Essential, второй игрок подключается обычным способом.
Каждый входит в СВОЙ аккаунт сервиса и получает содержимое самостоятельно.
Для YouTube каждый открывает свою видимую страницу Видео и разрешает воспроизведение.
Никакие токены и аудиофайлы не передаются игровому серверу.
Общим состоянием и очередью владеет **Minecraft-сервер**, а не Python backend.
Расстояние и измерение больше не ограничивают получение состояния.
Изменение громкости влияет только на локального слушателя.
На выделенном сервере нужны JAR и Fabric API, backend и вход в аккаунты серверу не нужны.

## Ограничения YouTube

В этой версии официальный IFrame находится в **отдельном видимом браузерном окне**,
а управление очередью находится в Minecraft. Встроенного Chromium-видеоплеера
в игровом HUD нет. При скрытии вкладки воспроизведение приостанавливается.
Нельзя использовать эту реализацию как скрытый audio-only источник.
Некоторые видео запрещают embed, имеют региональные/возрастные ограничения или рекламу.
Браузер может потребовать ручное нажатие Play. Live-видео не имеют обычного duration/seek.
Из-за рекламы, буферизации и ограничений браузера синхронизация приблизительная.
История просмотров и персональные рекомендации YouTube не реализуются через недоступные API.
Поиск расходует квоту общего Google-проекта.

## Сборка разработчиком

Готовому пользователю эти команды НЕ нужны. Надёжный путь — workflow Actions.
Для локальной сборки EXE нужен Windows x64, Python **3.12**, Java **17**:

```powershell
cd Music_Player/bridge
python -m pip install -r requirements.txt pyinstaller==6.11.1 psutil==6.1.1
python -m unittest discover -v
python -m PyInstaller --noconfirm --clean --onefile --windowed --name blockradio-backend --collect-all imageio_ffmpeg --collect-all keyring --hidden-import keyring.backends.Windows --add-data "youtube_player.html;." managed_backend.py
python smoke_windows.py
cd ../source
.\gradlew.bat build --no-daemon
```

Выходные файлы относительно корня репозитория:

- `Music_Player/source/build/libs/blockradio-0.3.0.jar`
- `Music_Player/bridge/dist/blockradio-backend.exe`

JAR, собранный без предварительной упаковки EXE, не обеспечивает автоматический backend.
Python 3.15.2 не является проверенной средой сборки этого пакета; готовый EXE содержит собственный Python.
Исходный `blockradio-0.2.0.jar` в репозитории — старый релиз, не устанавливайте его вместо artifact 0.3.0.

## Что проверить в реальной игре

1. Вход в оба сервиса, перезапуск Minecraft, восстановление сессий.
2. Поиск, обложки, следующая страница, мои лайки, Моя волна.
3. Play/Pause/Seek/Next/Previous, очередь из двух источников, Auto OFF/ON.
4. Два игрока через Essential: расстояние 5000 блоков, переход измерения,
   позднее подключение, разные локальные громкости, выход управляющего игрока.
5. Закрытие игры и отсутствие helper/FFmpeg после таймаута.

CI проверяет тесты, сборку, встроенный EXE и запуск/завершение standalone backend.
CI НЕ проверяет живые аккаунты, звук, GUI на разных GUI Scale, браузерный YouTube
или игровой сеанс двух клиентов. До такой проверки PR остаётся draft.
